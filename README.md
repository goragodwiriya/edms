# eDms — ระบบจัดการเอกสารอิเล็กทรอนิกส์

![PHP](https://img.shields.io/badge/PHP-%E2%89%A5%207.4-777BB4?logo=php&logoColor=white)
![MySQL](https://img.shields.io/badge/MySQL%20%2F%20MariaDB-InnoDB-4479A1?logo=mysql&logoColor=white)
![Version](https://img.shields.io/badge/version-7.0.4-4f46e5)
![License](https://img.shields.io/badge/license-MIT-green)

**eDms** (Electronic Document Management System) คือเว็บแอปพลิเคชันสำหรับ **จัดเก็บ เผยแพร่ และติดตามการเข้าถึงเอกสาร** ภายในองค์กร โรงเรียน หรือหน่วยงาน
ผู้อัปโหลดส่งเอกสารถึงแผนกที่เกี่ยวข้อง จัดเข้าตู้เก็บเอกสาร แล้วระบบจะบันทึกว่าใครดาวน์โหลดไฟล์ไหนไปกี่ครั้ง พร้อมแจ้งเตือนผ่านอีเมล LINE และ Telegram

สร้างบน [Now.js](https://github.com/goragodwiriya/nowjs) (front-end) และ [Kotchasan](https://www.kotchasan.com/) (PHP back-end)
รองรับภาษา **ไทย** และ **อังกฤษ** ใช้งานบนมือถือได้ในรูปแบบ PWA

## คุณสมบัติ

### จัดเก็บเอกสาร
- เอกสาร 2 แบบ: **แนบไฟล์** (หลายไฟล์ต่อเอกสาร) หรือ **ลิงก์** ไปยัง URL ภายนอก
- เลขที่เอกสารอัตโนมัติ กำหนดรูปแบบได้ (ค่าเริ่มต้น `DOC%Y%M-` + เลข 4 หลัก) หรือกรอกเองได้ ระบบตรวจเลขซ้ำให้
- ระบุวันที่เอกสาร ชื่อเรื่อง และรายละเอียด
- **ส่งถึงหลายแผนก** ได้ในเอกสารเดียว
- **ตู้เก็บเอกสาร** สำหรับจัดหมวดหมู่ พิมพ์ชื่อตู้ใหม่ในฟอร์มได้เลย ระบบสร้างให้ตอนบันทึก
  (ติดตั้งมาพร้อมตู้ตั้งต้น: คำสั่ง, คู่มือ, ทรัพย์สิน)
- กำหนดชนิดไฟล์และขนาดไฟล์ที่อนุญาตให้อัปโหลด

### ค้นหาและดาวน์โหลด
- สมาชิกที่สังกัดแผนก เห็นเฉพาะเอกสารที่ส่งถึงแผนกของตัวเอง
- กรองตามช่วงวันที่และตู้เก็บเอกสาร ค้นหาจากชื่อเรื่อง เลขที่เอกสาร หรือชื่อไฟล์
- แสดงว่าผู้ใช้ดาวน์โหลดไฟล์ไหนไปแล้วบ้าง
- เลือกได้ว่าคลิกแล้วจะ **ดาวน์โหลด** หรือ **เปิดไฟล์ในเบราว์เซอร์** (สำหรับไฟล์ชนิดที่รู้จัก)
- การ์ดบนหน้า Dashboard แสดงจำนวนเอกสารใหม่ใน 30 วันที่ยังไม่ได้ดาวน์โหลด

### ติดตามการเข้าถึง
- นับจำนวนครั้งที่สมาชิกแต่ละคนดาวน์โหลดแต่ละไฟล์ (รวมถึงการเปิดลิงก์)
- **ประวัติการดาวน์โหลด** รายไฟล์: ใคร สถานะสมาชิก ครั้งล่าสุดเมื่อไร และกี่ครั้ง
- ไฟล์ถูกเก็บด้วยชื่อสุ่ม และเปิดได้ผ่านระบบเท่านั้น (ตรวจสิทธิ์ทุกครั้ง) เข้าถึงโฟลเดอร์ไฟล์โดยตรงไม่ได้

### การแจ้งเตือน
- แจ้งเอกสารใหม่ทาง **อีเมล**, **LINE** และ **Telegram** ถึงผู้ดูแลระบบและผู้ที่มีสิทธิ์จัดการระบบเอกสาร
- ผู้ใช้ผูกบัญชี LINE / Telegram กับโปรไฟล์ของตนเอง (webhook อยู่ใน `line/` และ `telegram/`)

### ผู้ใช้และระบบ
- สมัครสมาชิก / เข้าสู่ระบบ / ลืมรหัสผ่าน / ยืนยันอีเมล
- เข้าสู่ระบบด้วย Google, Facebook, LINE หรือ Telegram
- กำหนดแผนก สถานะผู้ใช้ และสิทธิ์รายบุคคล พร้อมสิทธิ์ตั้งต้นของสมาชิกใหม่
- จำกัดจำนวนครั้งการเข้าสู่ระบบผิด (ป้องกัน brute-force)
- จัดการภาษา เมนู หมวดหมู่ และตั้งค่าระบบผ่านหน้าเว็บ
- บันทึกประวัติการใช้งาน (usage log)
- ตั้งค่าผู้ให้บริการ AI (Claude, Gemini, DeepSeek, OpenAI-compatible) ผ่าน `Gcms/Ai`
- PWA: ติดตั้งบนหน้าจอโฮมได้ มี service worker และ manifest

> ไฟล์ `Now/dist/*` (front-end ที่ build แล้ว) รวมมาในโปรเจ็คแล้ว ผู้ใช้ทั่วไปไม่ต้องติดตั้ง Node.js

## การติดตั้ง

1. **ดาวน์โหลดโปรเจ็ค**

   ```bash
   git clone https://github.com/goragodwiriya/edms.git
   ```

   หรือดาวน์โหลดเป็น ZIP แล้วแตกไฟล์ไปยัง document root ของเว็บเซิร์ฟเวอร์

2. **เตรียมฐานข้อมูล** — ตัวติดตั้งจะสร้างฐานข้อมูลให้ถ้าบัญชี MySQL มีสิทธิ์ ถ้าไม่มีสิทธิ์ให้สร้างไว้ก่อน

   ```sql
   CREATE DATABASE edms CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

3. **กำหนดสิทธิ์เขียน** ให้โฟลเดอร์ `settings/` และ `datas/` (ถ้ายังไม่มี ตัวติดตั้งจะพยายามสร้างให้)

   ```bash
   mkdir -p settings datas
   chmod -R 775 settings datas
   ```

4. **เปิดตัวติดตั้งผ่านเบราว์เซอร์**

   ```
   http://localhost/edms/install/
   ```

   ทำตามขั้นตอน: ตรวจความพร้อมของเซิร์ฟเวอร์ → ตรวจสิทธิ์เขียนโฟลเดอร์ → สร้างบัญชีผู้ดูแลระบบ → ตั้งค่าฐานข้อมูลและติดตั้ง

5. **ลบหรือปิดการเข้าถึงโฟลเดอร์ `install/`** หลังติดตั้งเสร็จ

---

## การอัปเกรด

1. **สำรองฐานข้อมูล** และโฟลเดอร์ `settings/`, `datas/`
2. เขียนทับไฟล์โปรเจ็คด้วยรุ่นใหม่ (ห้ามทับ `settings/` และ `datas/`)
3. เปิด `http://your-host/edms/install/` ระบบจะตรวจพบรุ่นเก่าและเข้าสู่โหมดปรับรุ่นเอง
   กรอกบัญชีผู้ดูแลระบบและยืนยันว่าสำรองฐานข้อมูลแล้ว จึงจะเริ่มปรับรุ่น

ตัวปรับรุ่นจะ **ตรวจก่อนแตะฐานข้อมูล** (`install/preflight.php`) ถ้าเงื่อนไขไม่ครบจะหยุดพร้อมบอกวิธีแก้ ก่อนแก้ไขฐานข้อมูล

**ปรับรุ่นจาก eDms รุ่นเดิม (6.x)** ได้โดยตรง ตัวปรับรุ่นของโมดูล (`modules/dms/install/upgrade.php`) จะย้ายแผนกและตู้เก็บเอกสารไปยังตาราง `dms_meta`
เปลี่ยนชื่อคอลัมน์ให้ตรงกับรุ่นใหม่ และย้ายรูปแบบเลขที่เอกสารและสิทธิ์ตั้งต้นของสมาชิกมาให้

## การใช้งานเบื้องต้น

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลที่สร้างตอนติดตั้ง
2. **ปรับรายชื่อแผนก** ที่ การตั้งค่า → แผนก (ติดตั้งมาพร้อม: บริหาร, จัดซื้อจัดจ้าง, บุคคล) แล้วกำหนดแผนกให้สมาชิกแต่ละคน
3. ตรวจ **ตั้งค่าโมดูล** ที่ การตั้งค่า → ระบบจัดเก็บเอกสาร: รูปแบบเลขที่เอกสาร ชนิด/ขนาดไฟล์ที่อัปโหลดได้ และสิทธิ์ตั้งต้นของสมาชิกใหม่
4. ผู้ที่มีสิทธิ์อัปโหลด เพิ่มเอกสารที่เมนู ระบบจัดเก็บเอกสาร → **อัปโหลด เอกสาร** เลือกแผนกที่จะส่งถึงและตู้เก็บเอกสาร แล้วแนบไฟล์หรือใส่ลิงก์
5. สมาชิกดูและดาวน์โหลดเอกสารได้ที่เมนู ระบบจัดเก็บเอกสาร → **รายการของ เอกสาร**
6. ผู้อัปโหลดเปิดหน้าไฟล์ของเอกสาร เพื่อดู **ประวัติการดาวน์โหลด** ของแต่ละไฟล์

## สิทธิ์การใช้งาน

โมดูลเพิ่มสิทธิ์ 3 รายการ กำหนดให้สมาชิกได้ที่หน้าจัดการสมาชิก

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| `can_download_dms` | ดูรายการเอกสารและดาวน์โหลดไฟล์ (สิทธิ์ตั้งต้นของสมาชิกใหม่) |
| `can_upload_dms` | เพิ่ม แก้ไข และลบเอกสาร ดูประวัติการดาวน์โหลด |
| `can_manage_dms` | จัดการตู้เก็บเอกสาร และได้รับแจ้งเตือนเมื่อมีเอกสารใหม่ |

ถ้าตั้งค่าเป็น **"อัปโหลดได้เฉพาะแผนกของตัวเอง"** ผู้อัปโหลดที่สังกัดแผนกจะส่งเอกสารได้เฉพาะแผนกของตัวเอง
และแก้ไขได้เฉพาะเอกสารที่ตัวเองสร้าง (ผู้ดูแลระบบไม่ถูกจำกัด)

## โครงสร้างโปรเจ็ค

```
edms/
├── index.php            หน้าหลักของเว็บ
├── api.php              จุดเรียก API (ใช้กับ front-end และ Bearer token)
├── export.php           ดาวน์โหลด/ส่งออกไฟล์
├── load.php             กำหนดค่าคงที่ (ROOT_PATH, DEBUG, DATA_FOLDER ...)
├── manifest.json        PWA manifest
├── service-worker.js    PWA service worker
├── Kotchasan/           PHP framework
├── Now/                 Now.js framework (source ใน Now/js, build แล้วใน Now/dist)
├── Gcms/                ไลบรารีกลาง (Config, Api, Line, Telegram, Sms, Ai ...)
├── modules/
│   ├── dms/             ระบบจัดเก็บเอกสาร: เอกสาร ไฟล์ ดาวน์โหลด ประวัติ แจ้งเตือน ตั้งค่า
│   ├── index/           ระบบสมาชิก ผู้ใช้ สิทธิ์ ภาษา เมนู ตั้งค่า dashboard
│   ├── export/          แม่แบบพิมพ์เอกสาร
│   ├── download/        ระบบอัปโหลด/ดาวน์โหลดไฟล์ของแกน
│   └── timeline/        ไทม์ไลน์กิจกรรม
├── templates/           แม่แบบหน้าเว็บ (HTML) ของ front-end (templates/dms = หน้าของระบบเอกสาร)
├── language/            ไฟล์ภาษา th / en
├── install/             ตัวติดตั้ง ตัวปรับรุ่น และสคริปต์ CLI
├── line/  telegram/     webhook ของ LINE และ Telegram
├── settings/            ค่ากำหนด (config.php, database.php) — สร้างตอนติดตั้ง
└── datas/               ไฟล์เอกสาร (datas/dms/) แคช log รูปภาพ — สร้างตอนติดตั้ง
```

โมดูล `dms` เป็นอิสระ มี `controllers/`, `models/`, `install/database.sql`, `install/upgrade.php` และ `tests/` ของตัวเอง

## ฐานข้อมูล

ตารางทั้งหมดใช้ prefix ที่กำหนดตอนติดตั้ง (ค่าเริ่มต้น `app_`)

| โมดูล | ตาราง |
|---|---|
| core | `category`, `language`, `logs`, `login_attempt`, `migration`, `number`, `user`, `user_meta`, `user_session` |
| dms | `dms` (เอกสาร), `dms_files` (ไฟล์แนบ), `dms_meta` (แผนก/ตู้เก็บเอกสาร), `dms_download` (สถิติการดาวน์โหลด) |
| timeline | `timeline_idempotency` |

นิยามตารางของโมดูลอยู่ที่ `modules/dms/install/database.sql` ที่เดียว ทั้งตัวติดตั้งและตัวปรับรุ่นอ่านจากไฟล์นั้น

## การตั้งค่า

| ไฟล์ | หน้าที่ |
|---|---|
| `settings/database.php` | การเชื่อมต่อฐานข้อมูลและ prefix |
| `settings/config.php` | ชื่อเว็บ เขตเวลา และค่าของระบบเอกสาร (แก้ได้จากหน้าตั้งค่าโมดูล) |
| `load.php` | `DEBUG` (0 = เฉพาะ error ร้ายแรง, 2 = แสดงบนหน้าจอ ใช้เฉพาะตอนพัฒนา) และ `LOG_DESTINATION` |

ค่าของระบบเอกสารใน `config.php`:

```php
'dms_prefix'          => 'DOC%Y%M-',   // นำหน้าเลขที่เอกสาร (%Y = ปี, %M = เดือน)
'dms_format_no'       => '%04d',       // รูปแบบตัวเลข
'dms_file_typies'     => ['doc', 'ppt', 'pptx', 'docx', 'rar', 'zip', 'jpg', 'pdf'],
'dms_upload_size'     => 2097152,      // ขนาดไฟล์สูงสุด (bytes) ไม่เกิน upload_max_filesize ของเซิร์ฟเวอร์
'dms_download_action' => 0,            // 0 = ดาวน์โหลดไฟล์, 1 = เปิดไฟล์ในเบราว์เซอร์
'dms_upload_options'  => 0,            // 0 = อัปโหลดได้ทุกแผนก, 1 = เฉพาะแผนกของตัวเอง
'default_user_permissions' => ['can_download_dms'],
```

การแจ้งเตือนอีเมล / LINE / Telegram / SMS, การเข้าสู่ระบบด้วยโซเชียล และผู้ให้บริการ AI ตั้งค่าได้จากหน้าตั้งค่าระบบหลังเข้าสู่ระบบ

## สำหรับนักพัฒนา

```bash
npm install
npm run dev          # Vite dev server
npm run build        # build ทุกชุดไฟล์ใน Now/dist
npm run build:core   # build เฉพาะ core
```

ชุดทดสอบของโมดูลเอกสาร (ต้องมี MySQL ตาม `settings/database.php` สร้างฐานทดสอบของตัวเองแล้วลบทิ้งเมื่อจบ):

```bash
php modules/dms/tests/run.php [--db=<ชื่อฐานทดสอบ>] [--keep]
```

สคริปต์ CLI ในโฟลเดอร์ `install/`:

| สคริปต์ | ใช้ทำอะไร |
|---|---|
| `cli-fresh.php` | ติดตั้งสคีมาใหม่ลงฐานเปล่า (ใช้สร้างฐานทดสอบ ต้องมี `settings/database.php` อยู่แล้ว) |
| `cli-upgrade.php` | รันตัวปรับรุ่นจากบรรทัดคำสั่ง (ต้องระบุ `--confirm-backup`) |
| `cli-verify.php` | ตรวจว่าสคีมาและจำนวนแถวผ่านเกณฑ์หลังปรับรุ่น |
| `cli-language.php` | ตรวจคีย์ภาษาที่โค้ดเรียกใช้แต่ไฟล์ภาษายังไม่มี |
| `cli-testdb.php`, `cli-testsecurity.php` | ชุดทดสอบตัวปรับรุ่นและความปลอดภัยของแกน |
| `cli-check-core.php`, `cli-sync-core.php` | เครื่องมือของผู้ดูแลโปรเจ็ค ใช้ตรวจ/ซิงก์ไฟล์แกนกับโปรเจ็คต้นแบบ |

แนวทางที่ใช้ในโปรเจ็ค:

- ฝั่ง PHP ใช้ namespace ตามโมดูลและไฟล์ เช่น `Dms\Write\Controller`, `Dms\Documents\Model`
- endpoint ของโมดูลอยู่ที่ `api/dms/<controller>/<action>` เช่น `api/dms/write/save`
- ฝั่ง front-end เขียนเป็น HTML template (`templates/dms/`) + `modules/dms/admin.js` (Now.js)
- ข้อความทั้งหมดผ่านระบบภาษา (`language/th.php`, `language/en.php`) ไม่ฮาร์ดโค้ด
- โฟลเดอร์ `Kotchasan/`, `Now/`, `Gcms/`, `modules/index/` และ `install/` เป็นแกนที่ใช้ร่วมกับโปรเจ็คอื่น
  การแก้ไขระดับเฟรมเวิร์กควรส่งไปที่ [Now.js](https://github.com/goragodwiriya/nowjs) หรือ [Admin Framework](https://github.com/goragodwiriya/adminframework)

## ความปลอดภัย

- `.htaccess` ปิด directory listing และบล็อกการเข้าถึงไฟล์ `.md`, `.sql`, `.log`, `.bak` ฯลฯ
- ไฟล์เอกสารใน `datas/dms/` ถูกบล็อกด้วย `.htaccess` ของตัวเอง เปิดได้ผ่าน `api/dms/download` ซึ่งตรวจสิทธิ์ก่อนเสมอ
- รหัสผ่านถูกเก็บแบบ hash และจำกัดจำนวนครั้งการเข้าสู่ระบบผิด
- **หลังติดตั้งต้องลบหรือปิดโฟลเดอร์ `install/`**
- ใช้ `DEBUG = 0` บน production และอย่า commit `settings/` หรือ `datas/` (อยู่ใน `.gitignore` แล้ว)
- ถ้าใช้ Nginx ต้องเขียนกฎบล็อก `datas/`, `settings/` และไฟล์ข้างต้นเอง เพราะ Nginx ไม่อ่าน `.htaccess`

พบช่องโหว่ด้านความปลอดภัย กรุณาแจ้งผู้พัฒนาโดยตรงก่อนเปิดเผยสาธารณะ
